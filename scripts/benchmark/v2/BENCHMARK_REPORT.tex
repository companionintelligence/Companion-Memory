\begin{abstract}
\noindent A fully local, head-to-head evaluation of six agent-memory systems on a single
synthetic persona, with no cloud calls.\footnote{Cloud-only providers (Honcho, RetainDB,
Supermemory, Memori) were excluded by the local-only constraint. Mem0 was run self-hosted
(open-source library + Chroma) against local models, not its hosted SaaS.} On a 100-question
flat/relational corpus the top three are a statistical tie --- \textbf{naive 79}, \textbf{mem0 78},
\textbf{CI-Server 75} (answer accuracy/100) --- followed by \textbf{Holographic 69}, \textbf{OpenViking 47},
and \textbf{Hindsight 25}. On \emph{structured} tasks (relationship enumeration, temporal supersession),
the workloads a knowledge graph is built for, \textbf{CI-Server leads}: best temporal, best enumeration,
best retrieval completeness, at top-tier query latency. Plain vector RAG is brutally cost-effective for
one-shot fact lookup; the graph's edge appears on relationship traversal and ``what is true now.''
\end{abstract}

\section{Method}

\textbf{Corpus.} One synthetic persona (``Max Turnquist''): \textbf{90 hand-authored canonical facts}
(people, places, employers, relationships, multi-hop chains, facts that change over time), buried under
\textbf{400 distractor messages} (the same topics about \emph{other} people, plus low-signal filler) so a
fixed top-$k$ retriever cannot trivially win. Total \textbf{490 messages; top-10 \sapp 2\% coverage}.

\textbf{Uniform contract.} Each system runs in its own container exposing the same HTTP surface
(\texttt{reset}, \texttt{ingest}, \texttt{flush}, \texttt{retrieve}, \texttt{answer}); the orchestrator
speaks only this contract.

\textbf{Two-phase, fair by construction.}
\begin{itemize}
  \item \emph{Phase A --- ingest/extraction:} every system ingests the identical corpus using the same
  extractor LLM (\texttt{gemma-4-31b-it-abliterated}) and the same embeddings
  (\texttt{nomic-embed-text}).\footnote{Hindsight uses its built-in \texttt{bge-small} embedder, a flagged
  minor confound. Holographic uses \emph{no} LLM and \emph{no} embeddings (SQLite FTS5 + HRR).} This isolates
  the memory \emph{architecture}, not the model.
  \item \emph{Phase B --- answer + judge:} a single, constant retrieval-augmented answerer and LLM judge
  (\texttt{ornstein-3.6-27b}) is used for \emph{all} systems, so we compare memory layers, not answer-writers.
\end{itemize}

\textbf{Two scored dimensions.} \emph{Answer}: did the constant answerer, given the system's retrieved
context, produce a correct final answer? \emph{Storage}: was the gold fact actually present in the
\emph{raw retrieved context}?\footnote{Storage isolates ``did the memory store + surface the fact'' from
``did the answerer phrase it well.'' A system can have high storage but lower answer, or vice versa.}

\section{Question taxonomy}

Three suites span nine classes. Every gold answer is grounded in exactly one canonical fact, so a miss is a
retrieval/answer failure, not a missing fact.

\subsection*{Suite A --- Broad recall (100 questions)}
\begin{description}
  \item[\texttt{flat-recall} (34)] A single atomic fact stated once. \emph{``What instrument does Max play?''}
  $\to$ violin. Probes whether the system surfaces one stated fact from under 400 distractors. LLM-judged.
  \item[\texttt{relational} (22)] One relationship hop. \emph{``Where do Max's parents live?''} $\to$ Portland.
  \item[\texttt{multi-hop} (22)] Two or more hops. \emph{``What does Max's brother-in-law do for work?''}
  $\to$ cardiologist (Max $\to$ sister Anita $\to$ husband Raj $\to$ occupation).
  \item[\texttt{temporal-update} (22)] Facts that changed; asks for the current value. \emph{``What city does
  Max currently live in?''} $\to$ Denver, not the prior Portland. Probes supersession.
\end{description}

\subsection*{Suite B --- Structured / agentic (37 questions)}
\begin{description}
  \item[\texttt{temporal-update} (20)] As above, both directions (current \emph{and} prior value).
  \item[\texttt{enumeration} (10)] ``List all X'' set queries. \emph{``List all of Max's family members.''}
  Scored by \textbf{deterministic set recall} --- the fraction of gold members surfaced --- with no LLM
  judge.\footnote{Set recall is reproducible and unspinnable: it counts how many of the canonical members
  appear, in the answer and (for storage) in the retrieved context.} Probes returning the \emph{complete}
  typed set, the graph's structural strength.
  \item[\texttt{aggregation} (7)] Counts and single-target filters. \emph{``How many cities has Max lived
  in?''} $\to$ 2. LLM-judged.
\end{description}

\subsection*{Suite C --- Absence / anti-hallucination (23 questions)}
\begin{description}
  \item[\texttt{absence} (16)] Baited negatives; the answer is \emph{no}, and each is baited with a tempting
  distractor about someone else. \emph{``Does Max work at Stripe?''} $\to$ No (that is his friend Lena's
  employer). Probes hallucination resistance. Scored by an existence-aware judge.\footnote{Correct only if
  the yes/no matches truth; a confident ``yes'' to a non-existent thing is a hallucination (wrong); ``I don't
  know'' is treated as not-a-hallucination.}
  \item[\texttt{presence-control} (7)] Genuine ``yes'' questions, so a system that blindly answers ``no''
  cannot game the absence suite.
\end{description}

\section{Conclusions}

\begin{itemize}
  \item \textbf{Flat fact lookup is a solved problem.} Two lightweight systems --- naive (vector) and
  Holographic (keyword/HRR\footnote{Holographic is keyword-only (SQLite FTS5 + HRR), with no semantic embedder.
  Its FTS5 layer ANDs query terms, so a raw natural-language question matches nothing; the adapter sends an
  \emph{OR-of-keywords} query (stopwords dropped), the same treatment naive and CI-Server's boosted search
  already apply to their keyword terms. Without it Holographic scores \sap0 --- an artifact of query format,
  not the system. Vendored from \texttt{NousResearch/hermes-agent} plugins/memory/holographic; the
  Hermes-runtime plugin glue was replaced by a thin adapter.}) both reach \sap70--79 at trivial cost. A
  graph is overkill here.
  \item \textbf{CI-Server's edge is structured / temporal / relational memory:} best temporal, best
  enumeration, best retrieval completeness, most decisive on present facts, at \sap80\,ms recall and
  concurrency-safe.
  \item \textbf{Trade-offs:} aggregation (counting) and absence-precision are weak spots (the
  flip side of surfacing rich context); multi-hop trails Mem0's consolidation; ingest is mid-pack.
  \item \textbf{The other graph/context-DB systems land below CI-Server on structured tasks.} OpenViking\footnote{%
  OpenViking (Volcengine/ByteDance) is a self-hostable ``context database''; we ran its server on the same local
  models (gemma-4-31b VLM + nomic embeddings). Its text-only-VLM path works on our image-free corpus. License:
  AGPL-3.0 --- a consideration for shipping, not for benchmarking.} is fastest at recall but slowest to ingest;
  Hindsight is slowest and weakest overall.
  \item \textbf{Holographic is the efficiency dark horse:} fastest ingest (5\,s) and recall (\sap5\,ms), 69/100
  on broad recall --- but it \emph{collapses} on enumeration (0.5/10): a keyword store cannot assemble a set,
  exactly where CI-Server's structure wins.
\end{itemize}
